Over the past year, I kept running into the same pattern.

I was working across different brands and products. Some needed a design system from scratch. Others had multiple product surfaces with shared functionality but different visual identities. But underneath all of them, the structure was surprisingly similar. The product changed. The look and feel changed. The token setup did not.

At some point, I stopped designing the product and started designing the system behind it.

That idea became Cipher.

## The shift

What I noticed across projects was that the most repetitive part of the work was not the UI itself. It was the system setup behind it.

Across projects, I kept rebuilding the same foundation in Figma: color ramps, aliases, semantic tokens, typography scales, radii, theme mappings, and shared UI patterns. What usually changed was the visual identity — brand color, tone, type choices, and surface treatment.

That made me realize I should stop treating each setup as a one-off deliverable and start treating it as a reusable structure.

## Why the existing workflow stopped scaling

If you have managed a design system in Figma, you probably know where this starts to hurt.

Variables and styles are powerful, but the editing experience is still painfully manual. Rename 50 variables? One by one. Delete an outdated scale? One by one. Fix mappings across modes? One by one. As systems grow, the work becomes less about design thinking and more about table maintenance.

And the bigger issue is that these tokens often live separately from the codebase where they actually matter. Figma becomes one source of truth. Code becomes another. Over time, they drift.

That disconnect bothered me more and more.

## How coding changed the way I designed

Around the same time, I was shifting more of my workflow into code.

Instead of designing entirely in Figma and handing off specs, I started building components directly in React, often using Cursor as part of the process. That changed a lot for me. The handoff got cleaner. Alignment got easier. In many cases, the code itself became the most accurate version of the design.

My design-in-code workflow started with Tailwind CSS, then expanded with shadcn/ui. But Tailwind was mostly primitive-driven, while shadcn leaned on flat semantic tokens. To support theming and personalization more cleanly, I started adding a mapping layer between the two. That eventually evolved into a three-tier structure: primitives, aliases, and semantics.

This token architecture became the real foundation behind Cipher.

## Why I built it

By that point, I knew exactly what kind of tool I wanted: something that could generate a full token system from a few brand decisions, make large-scale edits in Figma less painful, and connect cleanly to code through plain CSS.

I wanted the structure to be reusable, scalable, and flexible enough to support theming and personalization without rebuilding the foundation each time.

That tool became Cipher.

## The surprising part: I had never built a Figma plugin before

Cipher is a personal project. I built the first version in about two weeks of focused solo work, with everything designed directly in code. No Figma comps, no plugin background, and no prior experience with the Figma plugin ecosystem.

That is probably the part I find most worth sharing.

For a long time, the default way of making things was to learn first, then build: read the docs, understand the APIs, plan the architecture, and only then begin.

AI changes that order.

With tools like Cursor, I could start building immediately, solve problems in context, and learn through the process instead of before it. That felt like a real shift.

Not because AI removes the need to think, but because it lowers the cost of getting started. It makes it much easier to work through unfamiliar territory while still building toward something real.

For someone like me — a designer who codes, but is not traditionally a engineer — that changed what felt possible.

## What Cipher actually does

Cipher helps generate and manage a token-based design system inside Figma using native variables and styles.

You provide a few core inputs:

- brand and surface colors
- typography scale
- radius anchor
- font families

From that, Cipher generates a three-tier token structure:

**Primitives**  
Raw values like color ramps, spacing scales, font sizes, and durations.

**Aliases**  
A mapping layer between raw values and semantic tokens. Instead of updating hundreds of semantic assignments when a palette changes, you can remap a much smaller set of aliases — such as surface roles or font assignments — and let the system cascade from there.

**Semantics**  
The application layer: tokens like `--primary`, `--background`, `--border`, and `--destructive`, with light and dark mode built in. These define how values are used in the product.

That separation is what makes the system flexible. You can change a brand color or swap a surface palette without needing to rewrite every component. The architecture stays stable while the visual identity adapts.

## Built for Tailwind and shadcn

Cipher is designed around the way I already work in code: Tailwind CSS v4, shadcn/ui, and tokenized CSS custom properties.

It exports plain CSS variables that can be copied directly into the codebase, so token changes move from Figma to implementation with almost no translation layer in between.

## Why this project matters to me

Cipher is not just a plugin project for me. It represents a shift in how I think about design systems, tooling, and building.

It came out of repeated friction in real projects. It reflects my move from designing screens to designing systems. And it was only possible because AI-native workflows made it realistic for me to build something outside my original expertise.

I think more designers are going to work this way — not because everyone wants to become an engineer, but because the gap between seeing a missing tool and making one is getting smaller.
